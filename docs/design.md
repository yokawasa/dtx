# envx 設計書

## 1. 目的

envxは、ローカル環境における環境変数（APIキーなどの秘匿情報）を、安全かつ効率的に管理・切り替えるためのCLIツールである。

主な目的は以下の通り。

* 秘匿情報を安全に保存する
* 環境ごとの切り替えを高速に行う
* 誤った環境での実行を防ぐ

---

## 2. 設計原則

### 2.1 envは「完成品」として扱う

* 実行時にenvを合成しない
* 1回の実行で使用するenvは1つのみ
* 各envは単体で完結する

---

### 2.2 実行経路の強制

* 環境変数の利用は `envx run` のみ許可
* 通常コマンドと完全に分離する

```bash
npm start        # 秘匿情報なし
envx run ...     # 秘匿情報あり
```

---

### 2.3 状態と実行の分離

* `use` は状態の選択のみ
* `run` が唯一の実行ゲート

---

### 2.4 平文露出の最小化

* 通常は常に暗号化状態
* 実行・編集時のみ一時的に復号

---

## 3. ディレクトリ構造

```text
~/.envx/
  envs/
    dev.enc
    prod.enc
  current
```

### 各要素の役割

* envs/
  暗号化されたenvファイルを格納

* current
  現在選択されているenv名（平文の秘密は含めない）

---

### 権限設定

* ~/.envx : 700
* 各ファイル : 600

※ユーザー本人のみアクセス可能

---

## 4. CLI仕様

### 4.1 コマンド一覧

```bash
envx use <env>
envx current
envx ls
envx run [env] -- <command>
envx edit <env>
```

---

### 4.2 各コマンドの挙動

#### envx use

```bash
envx use dev
```

* currentを書き換えるのみ
* 環境変数は注入しない

---

#### envx run

```bash
envx run -- npm start
envx run prod -- npm start
```

* envを復号してコマンド実行
* env未指定時はcurrentを使用
* current未設定時はエラー

出力例：

```text
Using env: dev
```

---

#### envx current

```bash
envx current
```

* 現在のenv名を表示

---

#### envx ls

```bash
envx ls
```

* 利用可能なenv一覧を表示

---

#### envx edit

```bash
envx edit dev
```

* 安全にenvを編集

---

## 5. 実行モデル

### 5.1 実行フロー

envx run 実行時：

1. 対象envを特定
2. 暗号化ファイルを復号
3. 一時的に環境変数を注入
4. コマンドをexecで実行
5. 復号データを破棄

---

### 5.2 execの採用理由

* 親プロセスにenvを残さない
* プロセス構造がシンプル
* 環境変数の漏れを防ぐ

---

## 6. セキュリティ設計

### 6.1 分離

* 通常コマンドとenv付き実行を分離
* 明示的にenvxを通さないと利用不可

---

### 6.2 状態管理の安全性

* currentはenv名のみ保持
* 秘匿情報は一切含めない

---

### 6.3 平文管理

* 通常時は暗号化状態を維持
* 必要時のみ復号

---

### 6.4 編集時の安全性

一時ファイル方式を採用。

#### フロー

1. 一時ファイル作成（権限600）
2. 復号して書き込み
3. エディタで編集
4. 保存後に再暗号化
5. 一時ファイル削除

#### 特徴

* 平文の露出時間が短い
* 管理可能な範囲に閉じる

---

## 7. リスクと対策

### 7.1 同一ユーザー内のアクセス

* 完全防御は不可
* ツールの目的は「誤操作防止」

---

### 7.2 誤環境での実行

対策：

* envx run時にenv名表示
* 危険env（prodなど）は確認可能

---

### 7.3 平文漏洩

対策：

* 暗号化保存
* 一時ファイル方式
* 即時削除

---

## 8. 設計の特徴

* 挙動が予測可能
* 状態と実行の責務分離
* CLIとして直感的
* 最小限のコマンドセット

### 1. dotenvxとの具体的な連携方法

envxは暗号処理そのものを再実装せず、dotenvxを暗号化・復号・実行時注入のバックエンドとして利用する。

#### 基本方針

* envxは「どのenvを使うか」を管理する
* dotenvxは「envをどう暗号化・復号するか」を担当する
* `envx run` は、対象envを決定したうえでdotenvx経由でコマンドを実行する

#### envファイルの扱い

内部保存形式はdotenvx互換のenvファイルとする。

```text
~/.envx/
  envs/
    dev
    prod
  current
  keys/
    dev
    prod
```

* `envs/<env>` はdotenvxで暗号化されたenvファイル
* `keys/<env>` は対象envの復号キーを保持する
* env名とファイル名は1対1で対応する

※ 既存案の `dev.enc` のような拡張子を使うか、拡張子なしにするかは実装時に決定する。

#### run連携

```bash
envx run -- npm start
envx run prod -- npm start
```

内部的には以下の流れに変換する。

1. 対象envを決定
2. 対象envの復号キーを読み込む
3. dotenvxにenvファイルと復号キーを渡す
4. dotenvx経由でコマンドを実行する

イメージ：

```bash
DOTENV_PRIVATE_KEY=... dotenvx run -f ~/.envx/envs/dev -- npm start
```

envx側では、ユーザーが直接 `DOTENV_PRIVATE_KEY` を意識しなくてよい状態を目指す。

#### edit連携

```bash
envx edit dev
```

編集時は一時ファイルを利用する。

1. `envs/dev` を一時ファイルへ復号
2. エディタで編集
3. 保存後にdotenvxで再暗号化
4. 暗号化結果を `envs/dev` へ反映
5. 一時ファイルを削除

このとき、既存の公開鍵・秘密鍵を再利用するか、新しい鍵を発行するかのルールを明確化する必要がある。

#### エラー設計

以下を明確に分ける。

* dotenvxが見つからない
* envファイルが存在しない
* 復号キーが存在しない
* 復号に失敗した
* 実行コマンドが失敗した

envxはdotenvxのエラーをそのまま露出せず、envxの文脈で理解できるメッセージに変換する。

```text
envx: failed to decrypt env "prod"
envx: dotenvx is not installed
envx: current env is not set
```

### 2. 暗号鍵の管理方法

暗号鍵は、envファイル本体よりも強く保護する必要がある。envxでは、鍵の保存先を抽象化し、最初は実装しやすい方式から始める。

#### 管理対象

dotenvxの暗号化モデルに合わせ、少なくとも以下を扱う。

* 公開鍵
  envファイルに含めてもよい暗号化用の鍵

* 秘密鍵
  復号に必要な鍵

envxが特に保護すべき対象は秘密鍵である。

#### 保存方式の候補

##### ローカルファイル方式

```text
~/.envx/
  keys/
    dev
    prod
```

* 実装が単純
* クロスプラットフォームで扱いやすい
* ファイル権限は600に固定
* 同一ユーザー内の完全防御はできない

MVPではこの方式を第一候補とする。

##### パスフレーズ方式

秘密鍵をさらにパスフレーズで暗号化して保存する。

* 秘密鍵ファイル単体の漏洩に強い
* 実行時にパスフレーズ入力が必要
* 自動実行やスクリプト用途との相性が悪い

CLIツールとしての利便性を落とすため、初期実装では必須にしない。

##### OSキーチェーン方式

macOS Keychain、Windows Credential Manager、Linux Secret Serviceなどを利用する。

* OSの保護機構を利用できる
* ユーザー体験がよい
* OSごとの差異が大きい
* CIやヘッドレス環境で扱いにくい

将来的なオプションとして検討する。

#### 推奨方針

初期実装では以下の方針とする。

1. 秘密鍵は `~/.envx/keys/<env>` に保存
2. 権限は600を強制
3. `envx doctor` で権限不備を検出
4. 将来的にkey providerを差し替え可能にする

```text
KeyProvider
  file
  passphrase
  os-keychain
```

envx本体は保存方式に依存せず、KeyProvider経由で秘密鍵を取得する。

### 3. シェル統合

シェル統合は、通常利用時のミスを減らすための補助機能とする。環境変数の注入は引き続き `envx run` のみに限定し、シェル統合によって現在のシェルへ秘密情報を常駐させない。

#### 補完機能

対象シェル：

* zsh
* bash
* fish

補完対象：

* サブコマンド
* env名
* `run` のオプション

例：

```bash
envx use <TAB>
envx run <TAB>
```

env名補完は `~/.envx/envs/` の一覧を元に生成する。

#### プロンプト表示

現在選択中のenvをプロンプトに表示できるようにする。

例：

```text
[envx:dev] ~/app %
```

表示対象は `current` に保存されたenv名のみとする。秘密情報やenvの中身は一切読み込まない。

#### シェルフック

シェルフックは以下の目的に限定する。

* プロンプト表示用に現在env名を取得する
* 補完関数を読み込む
* 必要に応じて `envx current` の結果をキャッシュする

禁止事項：

* シェル起動時にenvファイルを復号しない
* `export` によって秘密情報をシェルへ常駐させない
* ディレクトリ移動だけでenvを自動注入しない

#### セットアップコマンド

将来的に以下のコマンドを追加する。

```bash
envx init shell
envx init completion
```

出力例：

```bash
eval "$(envx init shell)"
```

シェル設定ファイルへの自動追記は行わず、ユーザーが明示的に追加する形式を基本とする。
